# 事業計画 サブエージェント集（福田会計）

福田会計の事業計画を **業務カテゴリー別** にサブエージェント化して運用するためのディレクトリです。
`.claude/agents/` 配下に置かれた `*.md` は、Claude Code から専門担当者として呼び出せます。

## 実行環境とデータコネクタ

エージェント定義（`.claude/agents/*.md`）とスキル（`SKILL.md`）は**環境に依存しないテキスト資産**で、
ローカル／Web のどちらで実行しても共通で使える。一方、実データへの接続（MCPコネクタ）は
**実行環境ごとの設定**であり、環境によって使えるものが異なる。

| データ種別 | 主なコネクタ | 備考 |
|-----------|------------|------|
| 文書・資料 | **SharePoint**（ローカル実行時）／Google Drive | SharePoint はローカルのClaude Codeにコネクタ追加済み。Web実行環境では未提供 |
| 計画・タスク | Asana | プロジェクト「02.福田会計 目標設定／計画立案」が正本 |
| 会計・財務 | MoneyForward クラウド | 試算表・推移表・仕訳等 |
| 連絡・通知 | Gmail / Slack / Google Calendar | リマインド・回覧等 |

> SharePoint 上の資料を読む処理は、SharePoint コネクタのある**ローカル環境で実行**する。
> Web実行環境（コネクタ未提供）では該当処理はスキップし、Drive／直接アップロードで代替する。

## アーキテクチャ：PGEパターン＋オーケストレーター

本サブエージェント群は、**PGEパターン（Planner / Generator / Evaluator）** に
**オーケストレーター（司令塔）** を載せた構成で運用する。

```
        所長（人間）
            │  単一窓口
   ┌────────▼─────────┐
   │  オーケストレーター │  business-plan-orchestrator（Opus）
   │  （司令塔・Plan）   │  ・ヒアリング(AskUserQuestion) ・委譲 ・進捗管理（生成はしない）
   └───┬───────────▲──┘
       │委譲         │評価依頼／差し戻し
   ┌───▼───┐     ┌──┴──────────┐
   │Generator│ ←→ │ Evaluator      │ plan-evaluator（Sonnet）
   │カテゴリ別│     │ 成功基準でレビュー│ 基準を満たすまでループ
   │エージェント│   └────────────────┘
   └────────┘  finance / human-resources / sales-marketing / service-quality / strategy（Sonnet）
```

| 役割 | 担当 | モデル |
|------|------|--------|
| オーケストレーター（司令塔・Plan） | `business-plan-orchestrator` | Opus |
| Generator（各カテゴリーの計画生成） | カテゴリー別エージェント | Sonnet |
| Evaluator（成功基準でレビュー） | `plan-evaluator` | Sonnet |
| 単純なデータ取得・整形 | （必要に応じ） | Haiku |

### 運用上のポイント（動画の設計思想より）

- **司令塔は生成しない** — 管理と進捗に徹し、処理の複雑さを抑える
- **単一インターフェース** — 所長は司令塔とだけ対話すれば全体が進む
- **AskUserQuestion** — 計画段階で対話的にヒアリングし、手戻りを防ぐ
- **フィードバックループ** — Evaluator が成功基準でレビューし、満たすまで生成と評価を繰り返す
- **モデル使い分け** — Opus は司令塔／戦略立案に限定、複雑作業は Sonnet、単純作業は Haiku でコスト最適化
- **最小権限** — 各 Generator は担当領域のデータソースに限定して扱う

## 基本方針：行動計画と数字計画の二本立て

すべてのカテゴリーで、事業計画を **「行動計画」** と **「数字計画」** の両輪で追いかける。

- **数字計画**（What を測る）… 売上・利益・件数などの目標値と実績、KPI・予実差異
- **行動計画**（How で動かす）… 数字を達成するための施策・アクション、担当・期限・進捗

各エージェントは、担当カテゴリーについてこの両方を管理する。
**「数字計画の各目標には、それを動かす行動計画を必ず紐づける」** ことを原則とし、
月次レビューでは「数字の達成度」と「行動の進捗」をセットで振り返る。

| # | カテゴリー | サブ領域 | ファイル | 状態 |
|---|-----------|---------|---------|------|
| 1 | 人材活動 | 採用 / 教育 / 評価 | `human-resources-planning.md` | 未着手 |
| 2 | サービス品質活動 | （未細分化） | `service-quality-planning.md` | 未着手 |
| 3 | 営業マーケ活動 | （未細分化） | `sales-marketing-planning.md` | 未着手 |

### 細分化の扱い方（設計方針）

サブ領域があるカテゴリーは、運用しながら以下のどちらかを選べる：

- **1エージェント内で章立てする** … サブ領域ごとにミッション・KPIの節を設ける（初期はこちらが軽量で推奨）
- **サブ領域ごとにエージェントを分ける** … 例 `human-resources-recruiting.md` / `human-resources-training.md` / `human-resources-evaluation.md`。担当者や判断基準が大きく異なる場合に有効

| カテゴリー | サブ領域と想定スコープ |
|-----------|----------------------|
| 人材活動 | **採用**＝採用計画・母集団形成・選考 / **教育**＝研修・OJT・スキル育成 / **評価**＝人事評価制度・査定・フィードバック |
| 戦略構築活動 | **事業計画**＝全社方針・中期計画の統括 / **外部委託**＝アウトソース方針・委託先選定 / **業務提携**＝アライアンス・協業先開拓 |

## 試作（テンプレート）について

まず **財務経理活動**（`finance-accounting-planning.md`）を試作しました。
これを「型」として、以下の共通構成を踏襲しながら残り4カテゴリーへ横展開します。

### 各エージェントの共通構成

1. **フロントマター** (`name` / `description`)
   - `description` に「いつ使うか（トリガーとなるキーワード・状況）」を具体的に書く
2. **ミッション** — そのカテゴリーで何を支援するか
3. **数字計画（主要KPI／管理指標）** — 定点観測する指標と目標値（初期セットは要ヒアリング）
4. **行動計画** — 数字を動かす施策・アクション（担当・期限・進捗）。数字計画の各目標に紐づける
5. **データソース** — MoneyForward / Google Drive / Asana など割り当てる連携先
6. **進め方の基本フロー** — 着手時の確認事項と作業手順
7. **判断・出力のルール** — 推測しない、要因と打ち手をセットで返す等
8. **確定済みの前提** — 福田会計で合意した数値・ルールを蓄積していく欄

## 関連スキル（カテゴリーから参照する定型業務）

カテゴリーをまたぐ反復業務は、`monthly-tax-audit` のような **スキル** として切り出し、
該当カテゴリーのエージェントから参照する。

| スキル | 内容 | 主担当カテゴリー |
|--------|------|----------------|
| `monthly-tax-audit` | 月次税務監査レビュー（仕訳CSV照合） | サービス品質活動 / 財務経理活動 |
| `bonus-calculation` | 担当者別売上集計と賞与計算（CSV→明細→賞与算定） | 人材活動（評価）× 財務経理活動 |

## 運用の進め方

1. 試作（財務経理活動）を実際に使い、フォーマットの過不足を確認する
2. ヒアリングで「確定済みの前提」欄を埋め、精度を上げる
3. フォーマットが固まったら、残り4カテゴリーを同じ型で作成する
4. 各カテゴリーを横断する論点は「戦略構築活動」エージェントで束ねる

## 使い方（呼び出し方）

Claude Code 上で該当カテゴリーの作業を依頼すると、`description` のキーワードに
合致した際に自動でサブエージェントが選ばれます。明示的に指名することも可能です。
