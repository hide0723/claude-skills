# Teams更新アプリ 期日後リマインドワークフロー

## 概要

Teamsの更新アプリ（Microsoft Teams Updates app）で期日を過ぎた提出物・更新依頼に対して、対象者へリマインドメッセージを自動送信するワークフロー。

---

## 事前確認事項

作業開始前にユーザーから以下を確認する（または会話から特定する）：

1. **リマインド対象の特定方法**
   - Teamsの更新アプリで未提出のリクエスト一覧をExcel/CSVでエクスポートしているか
   - または手動でリストを提供するか

2. **リマインド送信先**
   - Teams チャット（個別メッセージ）
   - Teams チャネル投稿
   - メール（Gmail経由）

3. **リマインドの文面**
   - 標準テンプレートを使うか、カスタム文面か

4. **対象絞り込み条件**
   - 何日超過からリマインド対象とするか（例：1日超過、3日超過）
   - 特定の更新リクエスト種別のみか

---

## Step 1: 期日超過リストの取得

### 方法A：ユーザーがExcel/CSVを提供する場合

ユーザーにTeamsの更新アプリから未提出一覧をエクスポートしてもらい、提供を受ける。

CSVの想定列構成：

| 列 | 内容 |
|----|------|
| 更新リクエスト名 | リクエストのタイトル |
| 担当者名 | 提出すべき人の氏名 |
| メールアドレス | 担当者のメールまたはTeamsアカウント |
| 期日 | 提出期限（日付） |
| ステータス | 未提出 / 提出済み / 期日超過 |

### 方法B：Asanaでタスク管理している場合

```
期日超過タスクを検索してください（Asana）
- 完了していない
- due_on が今日以前
- プロジェクト：[Teams更新管理プロジェクト名]
```

---

## Step 2: 対象者の絞り込み

以下の条件でリマインド対象を絞り込む：

```
TODAY = 本日の日付
超過日数 = TODAY - 期日

リマインド対象：
  - ステータスが「未提出」または「期日超過」
  - 超過日数 >= [ユーザー指定の閾値、デフォルト1日]
  - すでに本日リマインド済みでないこと（二重送信防止）
```

超過日数に応じてリマインドの強度を変える：

| 超過日数 | リマインドレベル | 対応 |
|---------|--------------|------|
| 1〜2日 | 軽度 | 通常のリマインドメッセージ |
| 3〜5日 | 中度 | 管理者CCつきメッセージ |
| 6日以上 | 重度 | 管理者へのエスカレーション通知も送信 |

---

## Step 3: リマインドメッセージの送信

### Teams チャットへの送信（Power Automate連携がある場合）

Power Automateフローのトリガー用WebhookURLを使って送信。ユーザーにWebhook URLを確認する。

### Gmailでのメール送信（Gmail MCP使用）

```
件名：【リマインド】{更新リクエスト名} の提出をお願いします

{担当者名} 様

{更新リクエスト名} の提出期限（{期日}）が{超過日数}日超過しています。

お早めにTeamsの更新アプリからご提出ください。
ご不明な点があればご連絡ください。

よろしくお願いいたします。
```

**メール送信の実施手順：**

1. リマインド対象者リストを確認
2. ユーザーに送信内容をプレビュー表示して承認を得る
3. Gmail MCPで1件ずつ送信（`mcp__Gmail__create_draft` でドラフト作成 → 確認後送信）

---

## Step 4: 送信ログの記録

送信完了後、以下の内容をまとめてユーザーへ報告する：

```
【リマインド送信完了レポート】
送信日時：YYYY年MM月DD日
送信件数：X件

[対象者リスト]
1. 氏名（期日超過X日）→ メール送信済み
2. 氏名（期日超過X日）→ メール送信済み
...

[エスカレーション対象（6日以上超過）]
・氏名（期日超過X日）→ 管理者へも通知済み
```

---

## Step 5: 定期実行の設定（オプション）

毎朝自動でリマインドを実行したい場合は、Claudeのルーティン（Routine）機能で定期実行を設定する。

**設定例：平日9:00に自動実行**

```
毎営業日午前9時に以下を実行：
1. 期日超過の提出物リストを確認
2. 対象者へリマインドメッセージを送信
3. 結果を管理者にメールで報告
```

設定時はユーザーに以下を確認：
- 実行時刻（デフォルト：平日9:00）
- 報告先メールアドレス
- 対象のプロジェクト/更新リクエスト種別

---

## 使用例

**ユーザーの発言例：**

> 「今週の月次報告で未提出の人にリマインドを送りたい」
> 「期日を3日超過した人に督促メールを送って」
> 「Teamsの更新アプリで未提出になっている一覧を確認してリマインドして」

**対応フロー：**

1. 未提出者リストをユーザーから受け取る（またはAsanaで検索）
2. 超過日数を計算して対象者を絞り込む
3. メッセージ内容をプレビューしてユーザーに確認
4. 承認後、Gmailドラフトを作成 → 確認後送信
5. 送信完了レポートを報告
