# 職階別の期待職能（税理士法人福田会計）

EMPグループの「給与テーブル期待職能（2024-09-01版）」を原型に、税理士法人福田会計の
グレード制度（T1〜EP／31グレード）に合わせて作成した期待職能表。

## 構成

内容は **`levels.py` の1箇所** にまとまっていて、md / xlsx / html はそこから生成する。
3つのファイルを個別に手直しすると必ずズレるので、**必ず `levels.py` を直して再生成する**こと。

```
Asana（正）           ← 職階・テーマ・期待される役割・測定指標・プロセス・昇格の条件
  └ asana_sync.py    ← Asana の説明欄 ⇄ levels.py の相互変換
levels.py             ← 内容（上記＋必要なインプット・運用ルール・要決定事項・在籍者）
                        ＋ グレード表（31グレード）を grade_rows() で生成
  ├─ build_md.py     → 職階別の期待職能.md    本文
  ├─ build_xlsx.py   → 職階別の期待職能.xlsx  A3横1枚の印刷用
  └─ build_html.py   → 職階別の期待職能.html          スマホ閲覧用（一般版）
                       職階別の期待職能_管理者版.html  同上（管理者版）

atc_map.py            ← 期待されるプロセス × アチーブメント（ATC）学習内容の対応
  └─ build_atc_xlsx.py → ATC対応表_福田会計.xlsx
```

`build_html.py` は `atc_map.py` も読み、各職階のプロセス行にATC記号のチップを付ける。

```bash
pip install openpyxl
python3 build_md.py && python3 build_xlsx.py && python3 build_html.py && python3 build_atc_xlsx.py
```

## Asana が正（2026-08-20〜）

各職階の **職階・テーマ・期待される役割・測定指標1／2・期待されるプロセス・昇格の条件** は
Asana を正とする。内容を変えるときは Asana を直し、そこから `levels.py` に取り込む。

```
02.福田会計 目標設定／計画立案 ＞ 🏫人材
  └ 評価：💮「この評価・報酬を決めているのは自分」といえる評価制度
      └ 評価ー役割：職務記述書を作成      ← 1タスク
          ├ T｜研究生                     ← 職階ごとのサブタスク（9件）
          ├ S｜担当職
          └ …（SS / M / SM / D / SD / P / EP）
```

`asana_sync.py` が説明欄の書式を決めている。`to_notes()` が levels.py → Asana、
`parse_notes()` が Asana → levels.py。`python3 asana_sync.py` で全9職階の往復テストが走る。
サブタスクの GID は同ファイルの `SUBTASK_GID` に持たせている。

**取り込みは Claude Code 経由で行う。** Asana MCP の認証がセッションに紐づいていて、
リポジトリ内のスクリプトから直接 Asana API を叩けないため、`parse_notes()` に渡す本文は
Claude が MCP で読み取って渡す。「Asanaから取り込んで」と指示すれば、9件を読んで
`levels.py` を書き換え、md / xlsx / html を再生成する。

Asana に載せないもの（`levels.py` が正のまま）:
必要なインプット／期待売上高・基本給／在籍者とグレード／運用ルール／要決定事項／ATC対応

## グレード表

`levels.py` の `GRADE_BANDS`（職階ごとの基本給上限・昇給幅・グレード数）から
`grade_rows()` が31グレードを1行ずつ生成し、md と html の「グレード表」に出す。
期待売上高は `expected_revenue()` が基本給上限から計算する（千円未満切上、万円は四捨五入）。
各職階の `revenue` / `salary` と一致することを確認済み。基本給テーブルを直すときは
`GRADE_BANDS` と各職階の `revenue` / `salary` の両方を直すこと。

在籍者の `roster` に持たせるグレードは、基本給を「グレード制度_基本給テーブル_福田会計」
（SharePoint / 2026-06-30更新）のレンジに当てはめたもの。基本給そのものはこのリポジトリに
持たせない。`GRADE_BANDS` は同テーブルの31行と全件一致することを確認済み。

**D（拠点長）以上は期待売上高の目安を出さない**（`NO_REVENUE` / `shows_revenue()`）。職階スライドの数値欄からも、グレード表の該当行からも落とし、組織運営と労働分配率で見る。

在籍者の並びは **入所年月日順、所長は最後**（`JOINED` / `CHIEF` / `roster_sorted()`）。
入所年月は表示せず並べ替えにだけ使う。未確認の人は所長の直前に置く。

在籍者は **職階までしか表示しない**。誰がどのグレードかは md にも一般版 html にも出さない
（グレード表に在籍列は置かず、`grade_rows()` も在籍者を返さない）。職階ごとの在籍者は
`roster_names()` が氏名と「所長」「総務兼任」などの補記だけを返す。
グレードそのものは `levels.py` の `roster` に持たせたまま、出力側で落としている。

## 一般版と管理者版

`build_html.py` は同じ内容から2本のHTMLを出す。違いは **誰がどのグレードかを出すかどうか、
その1点だけ**。

| | 一般版 | 管理者版 |
|---|---|---|
| ファイル | `職階別の期待職能.html` | `職階別の期待職能_管理者版.html` |
| グレード表の在籍列 | なし | あり（在籍者のいる行に色） |
| 職階スライドの在籍者 | 氏名のみ | 氏名＋グレード |
| 表紙 | ― | 取扱注意の帯＋一般版へのリンク |

**一般版のHTMLには、グレード別の在籍者を一切書き出していない**（CSSやJSで隠しているのでは
なく、そのデータをファイルに持たせていない）。ページを閲覧できる人がソースを見ても出てこない。
管理者版だけが `roster_by_grade()` を呼ぶ。

アーティファクトは既定で非公開で、閲覧できるのは共有した相手だけ。したがって
**「権限」の実体は、どちらのリンクを誰に渡すか**になる。ページ側にログインや役割判定はない。
管理者版のリンクを渡した相手は、その時点で全員分のグレードを見られる。

## EMP版からの主な変更点

| 論点 | EMP版 | 福田会計版 |
|---|---|---|
| 段階数 | 9段階（入社前・S・SS・CS・M・SM・GM・D・P） | 9段階（T・S・SS・M・SM・D・SD・P・EP） |
| CS（チーフスタッフ） | 独立した階層 | SS（主任）に統合 |
| 入社前 | 独立した階層 | 廃止。T（研究生）と重複するため |
| T（研究生） | なし | 新設。入口の職階。期待売上高・労働分配率は問わない |
| M・SM／D・SD | 記号ごとに1階層 | テーマを分けて別建て（M/SM、D/SD をそれぞれ独立） |
| 組織人数要件 | 20名／10名／6名／3名 | 15名／10名／6名／3名（所属人数 約10名に合わせて縮小） |
| 事業立ち上げ額 | 3億／1億 | 3,000万／1,000万（法人規模に合わせて1/10） |
| 売上基準 | 記載なし | グレード別「期待売上高」を明記（基本給テーブルと一致） |
| 資格要件 | 記載なし | 簿記3級（S）／簿記2級（SS）／税理士3科目（D）／税理士登録（P・EP）を仮置き |
| 残業ペナルティ | 記載なし | 月30時間超でグレードダウンを明記 |
| ハンドブック・MBS | EMPハンドブック／MBS1〜5 | 福田会計虎の巻（実在・日次更新）に置換。試験の中身は未整備・要決定 |

## アチーブメント（ATC）との対応

`atc_map.py` に、各職階の「期待されるプロセス」とATCの学習項目の対応を持たせている。
ATCは選択理論心理学（W.グラッサー）と成功哲学を土台に、実行力強化・習慣形成に特化した
講座で、300の基礎技術で構成される。学習項目は3系統17項目に整理した。

| 系統 | 記号 | 例 |
|---|---|---|
| 選択理論の基礎 | A1〜A7 | 全行動／内的コントロール／5つの基本的欲求／上質世界／致命的な7つの習慣／身につけたい7つの習慣／セルフカウンセリング |
| 目標達成技術 | B1〜B6 | 人生理念の明確化／目標設定／逆算計画／タイムマネジメント／実行力強化・習慣形成／可能思考 |
| 対人関係・組織 | C1〜C4 | リードマネジメント／ボスマネジメントからの脱却／質問による関わり／理念経営 |

**注意**: achievement.co.jp は本環境の egress 制限で直接参照できなかったため、学習項目は
公開されている二次情報と、所内 SharePoint の『グラッサー博士の選択理論』（所長フォルダ）
から構成した**提案**。実際の受講テキストと突き合わせて確定させること。

## 未確定箇所の印

本文中の **【要決定】** は制度自体が未整備の項目、**【仮】** は数値・条件が仮置きの項目。
どちらも `levels.py` の `DECISIONS`（本文「4. 未確定・要決定事項」）に対応する。
運用開始前に代表決裁が必要なものを10点挙げている。
